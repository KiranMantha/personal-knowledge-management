### **3. Creating Provider**

To use benefits of Query Client, we need to create a provider to wrap our application in client-side.

Before diving this, we need to create our provider file at this path.

*myapp/src/providers/query-client.provider.tsx*

```

    └── src/  
        └── providers/

```

And, now. We are going to fill this file.

### **4. Query Client Provider**

```
// my-app/src/providers/query-client.provider.tsx  
  
// QueryClientProvider is based on Context API, that's why this component should be Client Component  
'use client';  
  
import { isServer, QueryClient, QueryClientProvider } from '@tanstack/react-query';  
import { PropsWithChildren } from 'react';  
  
function createQueryClient() {  
  return new QueryClient({  
    defaultOptions: {  
      queries: {  
        staleTime: 1 * 60 * 1000, // To cache the data for 1 minute  
        refetchOnReconnect: false,  
        refetchOnWindowFocus: false,  
      },  
    },  
  });  
}  
  
let browserQueryClient: QueryClient | null = null;  
  
function getQueryClient() {  
  if (isServer) {  
    // In server, we are always creating new object because, we don't want to dehydrate all the data (from other requests) inside Query Client  
    console.log('SSR');  
    return createQueryClient();  
  } else {  
    // Using the same client, to access the cached data between Client Components  
    if (!browserQueryClient) {  
      browserQueryClient = createQueryClient();  
    }  
    return browserQueryClient;  
  }  
}  
  
export function ReactQueryClientProvider({ children }: PropsWithChildren<unknown>) {  
  const queryClient = getQueryClient();  
  
  return <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>;  
}
```

As you see above, we’re handling Query Client instances differently for CSR and SSR.

To prevent unnecessary hydration, we create new instance for each time in Server Components.

To share cached data between Client Components, we use the same instance.

### **5. Including the Provider to the Hierarchy**

To make Query Client available in both sides, we need to include our provider to the app.

To make this, we need to edit our *layout.tsx* file.

```
// my-app/src/layout.tsx  
  
import type { Metadata } from 'next';  
import { Inter } from 'next/font/google';  
import './globals.css';  
import ReactQueryClientProvider from '@/providers/query-client.provider';  
  
const inter = Inter({ subsets: ['latin'] });  
  
export const metadata: Metadata = {  
  title: 'Create Next App',  
  description: 'Generated by create next app',  
};  
  
export default function RootLayout({  
  children,  
}: Readonly<{  
  children: React.ReactNode;  
}>) {  
  return (  
    <html lang="en">  
      <body className={inter.className}>  
        // We're wrapping the children  
        <ReactQueryClientProvider>{children}</ReactQueryClientProvider>  
      </body>  
    </html>  
  );  
}
```

### **6. Creating Service**

Before creating the components, we need to create our service using Axios and TanStack Query.

```
// my-app/src/services/use-get-posts.ts  
  
import { isServer, useQuery } from '@tanstack/react-query';  
import axios, { AxiosResponse } from 'axios';  
  
export interface IPostModel {  
  userId: number;  
  id: number;  
  title: string;  
  body: string;  
}  
  
export const getPosts = async () => {  
  console.log('[services/get-posts] isServer: ', isServer);  
  
  try {  
    const endpoint = `https://jsonplaceholder.typicode.com/posts`;  
  
    const { data } = await axios.get<IPostModel[], AxiosResponse<IPostModel[]>>(endpoint);  
  
    return data;  
  } catch (error) {  
    console.error(error);  
    throw error;  
  }  
};  
  
// This part is Tanstack Query  
// We are using useQuery to cache our data for 10 minutes  
const useGetPosts = () => {  
  return useQuery({  
    queryKey: ['posts'],  
    queryFn: getPosts,  
    staleTime: 10 * 60 * 1000 // This will override the global staleTime  
  });  
};  
  
export default useGetPosts;
```

### **7. Creating Server Component**

```
my-app/  
    └── src/  
        ├── app/  
        │   └── posts/  
        │       └── page.tsx  
        └── components/  
            └── posts.tsx
```

We need to create 2 files.

* The first one is, the page which should be the server component.
* The second one is, the component which should be the client component.

```
// my-app/src/app/posts/page.tsx  
  
import { dehydrate, HydrationBoundary, isServer, QueryClient } from '@tanstack/react-query';  
import { Posts } from '@/components/posts';  
import { getPosts } from '@/services/use-get-posts';  
  
export default async function PostsRoute() {  
  console.log('[page/posts] Is Server:', isServer);  
    
  // Creating a new QueryClient instance  
  const queryClient = new QueryClient();  
  
  // Prefetching the data  
  await queryClient.prefetchQuery({  
    queryKey: ['posts'],  
    queryFn: getPosts,  
  });  
    
  // Dehydrating (making accessible the data and state over the client-side)   
  // the Query Client instance  
  return (  
    <HydrationBoundary state={dehydrate(queryClient)}>  
      <Posts />  
    </HydrationBoundary>  
  );  
}
```

### **8. Creating Client Component**

```
// my-app/src/components/posts.tsx   
  
'use client'; // Allows us to use React Hooks and other CSR stuffs (window object, state, ..).  
  
import useGetPosts from '@/services/use-get-posts';  
import { isServer } from '@tanstack/react-query';  
  
export function Posts() {  
  console.log('[components/posts] Is Server:', isServer);  
  
  // This is the service call, which will return the data  
  // that is already fetched and dehydrated by the Server Component (post/page.tsx)  
  const { data: posts, isLoading, isSuccess, isFetched } = useGetPosts();  
  
  if (isLoading) {  
    return <p>Loading...</p>;  
  }  
  
  if (isFetched) {  
    console.log('[components/posts] Fetched.');  
  }  
  
  if (isSuccess) {  
    console.log('[components/posts] Succeeded:');  
  }  
  
  return posts ? (  
    posts.map((post) => (  
      <p key={post.id}>  
        {post.id}) {post.title}  
      </p>  
    ))  
  ) : (  
    <p>No data</p>  
  );  
}
```

### **10) Tanstack Query Devtools**

Tanstack Query has a devtools package, that minimizes your effort to track and debug your requests and cached data.

We need to add this package to our app first.

```
# npm  
$ npm i @tanstack/react-query-devtools  
  
# pnpm  
$ pnpm add @tanstack/react-query-devtools
```

Then, we should edit our *layout.tsx* file again.

```
import type { Metadata } from 'next';  
import { Inter } from 'next/font/google';  
import './globals.css';  
import ReactQueryClientProvider from '@/providers/query-client.provider';  
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';  
  
const inter = Inter({ subsets: ['latin'] });  
  
export const metadata: Metadata = {  
  title: 'Create Next App',  
  description: 'Generated by create next app',  
};  
  
export default function RootLayout({  
  children,  
}: Readonly<{  
  children: React.ReactNode;  
}>) {  
  return (  
    <html lang="en">  
      <body className={inter.className}>  
        <ReactQueryClientProvider>  
          {children}  
          // We should add Devtools inside the Provider  
          <ReactQueryDevtools buttonPosition="bottom-right" />  
        </ReactQueryClientProvider>  
      </body>  
    </html>  
  );  
}
```

We added *ReactQueryDevtools* inside the *ReactQueryClientProvider.* This allows Devtools to track the requests. If you place the Devtools outside of the boundaries of Query Client, you’ll be facing errors.

In the bottom-right of the screen, you’ll be seeing an icon. After clicking on this icon, there’ll be a panel like below.

Press enter or click to view image in full size

![]()

This panel will display all the cached queries and mutations. In this article, we worked with useQuery and we’ll be looking into the Queries section.

Press enter or click to view image in full size

![]()

If you click on a cached data, you’ll be seeing data and functions like refetch, invalidate, reset, etc.

That means, the data is existed on the client side. And as you see in the top-right corner. it says it’s *fresh.*

Fresh data means, it’s not expired and it will be returned in the next query. Basically, it’s cached.
