> “I used to write 30 lines of JavaScript just to animate something on scroll. Now? Two lines of CSS. No, seriously.”

If you’ve been doing frontend work for a while, you know the ritual. You need an element to fade in when the user scrolls to it, so you reach for `IntersectionObserver`. You write the callback, the options object, the loop over your elements, the cleanup logic — and that's before you even touch a single line of animation CSS.

It works. But it always felt like a lot of machinery for something that’s fundamentally a *visual* problem.

Something has shifted over the last couple of years. CSS in 2024–2025 is not the same language it was five years ago. It has quietly grown powerful enough to handle a large chunk of what we used to delegate to JavaScript — not as a workaround or a hack, but as a first-class, browser-optimized solution.

This isn’t a “kill JavaScript” post. JS is still essential for data fetching, state management, and business logic. But for **visual interactions**? CSS is catching up fast — and in many cases, it’s already ahead.
